# Security policy

Report suspected vulnerabilities privately through the monitored contact published on the official `/security` page. Do not open a public issue containing Source URLs or profiles, QR images, pairing codes, inbox credentials or private keys, device tokens, APNs credentials, real work/result content, complete encrypted envelopes, or private deployment configuration.

Include the affected component and version, a concise impact description, and secret-free reproduction steps. Do not test against another person’s inbox, degrade the hosted service, retain accessed data, or publish before a reasonable remediation window is agreed.

Only the latest supported protocol-2 release receives security fixes. Protocol 1 is a frozen historical boundary and is not accepted by the V1.1 runtime.
